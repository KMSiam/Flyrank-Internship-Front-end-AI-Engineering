1. Server-Side Tool Contract & Zod Specification

The tool is isolated in src/lib/tools/promptAuditTool.js and registered under the contract name scorePromptEngineering. It accepts prompt text, target domain, and threshold constraints, enforcing schema validation via Zod before invoking the deterministic execution function.

Zod Input Schema Definition

export const promptAuditInputSchema = z.object({
  promptText: z
    .string()
    .min(5, "Prompt must be at least 5 characters long")
    .max(4000, "Prompt cannot exceed 4000 characters"),
  targetDomain: z
    .enum(["coding", "compliance", "analysis", "general"])
    .default("general"),
  minimumScoreThreshold: z
    .number()
    .min(0)
    .max(100)
    .optional()
    .default(70),
});

2. Four Distinct Tool Part Lifecycle States

Instead of unformatted JSON blobs, ToolPartRenderer.jsx binds each state of the tool invocation lifecycle to a purpose-built visual treatment:

1. Input Streaming Running

"What is it doing?" Pulsing radar icon with dynamic parameter counter, live token telemetry, and shimmering animated skeleton.

2. Input Available Ready

"With what input?" Collapsible pill inspector displaying validated parameters, domain tag, threshold, and character count.

3. Output Available Success

"What came back?" Rich PromptScoreCard rendering composite score badge, dimension bars, SVG bar chart, and recommendations.

4. Output Error Failed

"What went wrong?" Designed ToolErrorCard displaying error taxonomy, remediation steps, and an interactive Retry trigger.

3. Rich Component Visualization vs. Raw JSON Dump

Output-Available: PromptScoreCard.jsx

Renders structured analytical output as an enterprise scorecard with hand-crafted SVG dimension visualization and actionable checklists:

  • Composite Grade: Tier pill (EXCELLENT, GOOD, MODERATE, NEEDS WORK) with color coded ring.
  • Dimensional Metrics: Clarity (35%), Specificity (35%), and Guardrails (30%) progress indicators.
  • Hand-Rolled SVG Chart: Responsive SVG bar chart showing dimension weights without bulky chart libraries.
  • Remediation Checklist: Interactive bulleted recommendations for prompt optimization.
  • FinOps Telemetry: Latency in milliseconds and calculated token count.

Output-Error: ToolErrorCard.jsx

Designed failure boundary providing deterministic error containment rather than white-screen crashes or unhandled promise rejections:

  • Error Taxonomy: Distinct badge (e.g. ERR_INSUFFICIENT_CONTEXT).
  • User-Facing Remediation: Explains exactly what was missing (e.g., prompt brevity, missing constraints) in clear human language.
  • Interactive Recovery: Built-in "Retry Execution" button to re-trigger the pipeline with safe fallback parameters.
  • Safe Degradation: Prevents unhandled crashes in client chat streams.

An interactive demonstration harness was deployed at /generative-ui (mounted in src/app/generative-ui/page.jsx via src/components/tools/ToolLifecycleDemo.jsx) allowing evaluators to trigger both the successful end-to-end tool execution and the designed error boundary with real-time state visualization.

Tool Lifecycle Component State Machine

// Morphing tool state simulation & renderer
const runToolCycle = async (simulateFailure = false) => {
  setToolState("input-streaming");
  await sleep(650);

  setToolState("input-available");
  await sleep(550);

  if (simulateFailure) {
    const errorResult = await executePromptAudit({
      promptText: "TRIGGER_TOOL_ERROR: Missing context",
    });
    setToolOutput(errorResult);
    setToolState("output-error");
  } else {
    const result = await executePromptAudit({
      promptText: activePrompt,
      targetDomain: activeDomain,
      minimumScoreThreshold: 70,
    });
    setToolOutput(result);
    setToolState("output-available");
  }
};
