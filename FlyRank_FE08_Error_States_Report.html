1. Comprehensive Failure & Edge Case Inventory

Production AI applications fail in modes that traditional CRUD interfaces do not experience. Below is the systematic failure inventory and mitigation matrix engineered for the capstone:

Failure / Edge Scenario Root Cause in AI Context Engineered Mitigation Strategy UX State & Visual Treatment
Empty / Blank Input User submits whitespace or empty form. Client submit disabled; server validates with ERR_EMPTY_INPUT (HTTP 400). Disabled send button; graceful notice; zero unnecessary API traffic.
First-Run Empty State No active messages in conversation history. Designed onboarding view with 4 click-to-fill action cards and sabotage triggers. No dead-end "No messages"; actionable suggestions with 1-click execution.
Pending Token Delay (Slow Response) Model thinking phase or latency spike before 1st token. Layout-accurate skeleton matches exact avatar width and 3 text line-heights. Prevents Cumulative Layout Shift (CLS); smooth handoff to streaming text.
HTTP 429 Rate Limit Upstream model token quota exhausted. Server emits 429 status with Retry-After: 15; client parses error taxonomy. Designed amber error card with retry backoff countdown and retry action.
Mid-Stream Connection Drop Network severed after emitting initial tokens. SSE emits type: 'error'; client preserves partial tokens in bubble. Partial text retained; attached error card with "Retry this response" button.
Route Rendering Crash Unhandled exception in component hierarchy. App Router error boundaries (error.jsx, chat/error.jsx) trap error. Dedicated error boundary UI with working reset() action and home link.
Mobile Safari Viewport Bug iOS software keyboard shifts 100vh pinned input. Used min-h-[100dvh], overscroll-contain, and pb-[env(safe-area-inset)]. Input stays pinned above virtual keyboard; no rubber-band scroll collisions.

3. Micro-Interaction: "Buttons with a Brain" Retry Architecture

The retry button in StreamingChat.jsx is engineered with strict state choreography to avoid double submissions, prevent conversation corruptions, and provide clear user feedback:

Retry State Machine & Debounce

// Micro-interaction retry handler
const handleRetry = async (botMessageId, failedPrompt) => {
  if (retryingMessageId || status === 'streaming') return;
  
  // 1. Lock retry to prevent double clicks
  setRetryingMessageId(botMessageId);
  
  // 2. Clear error state on specific bot message
  setMessages(prev => prev.map(m => 
    m.id === botMessageId ? { ...m, error: null } : m
  ));

  // 3. Re-invoke stream using target turn in happy-path
  await executeStream(failedPrompt, botMessageId, 'none');
};

Retry Behavior Invariants

  • Turn-Targeted: Only re-submits the specific failed prompt, leaving preceding conversational history intact.
  • Double-Click Safe: Disabled during in-flight retry with dynamic spinner (animate-spin) and "Retrying turn..." label.
  • Deterministic Recovery: Overrides active sabotage mode to guarantee the retry recovers successfully into a completed stream.
  • Calm Motion Pass: Avoids sudden red flash-bangs; transitions in with soft amber border (border-amber-500/40) and gentle fade.
