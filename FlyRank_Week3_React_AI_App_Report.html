1. Executive Summary & Mentor Alignment

This project satisfies the Week 3 Foundations requirement to build a complete, production-ready React application independently using AI as an engineering co-pilot, following the architectural guidelines articulated by mentor Ishak. Rather than passively accepting raw AI output, the engineering methodology centered on an explore-plan-code-verify paradigm orchestrated within Google Antigravity (powered by Gemini 3.8 Flash High / Advanced Agentic Coding).

The result is PromptCraft Studio AI: an interactive, single-page application built in React 19 and Vite 8.3 that empowers engineers to compose dynamic prompts with live {{variable}} interpolation, evaluate prompt quality via heuristic static analysis (Clarity, Specificity, Guardrails), simulate streaming token output across frontier models, and monitor real-time FinOps API costs.

Mentorship Core Insight: As emphasized by mentor Ishak, the value of an AI assistant lies not in autonomous typing, but in accelerating the translation of structured specifications into modular components while the engineer exercises strict gatekeeping over state flow, lifecycle boundaries, and edge-case resilience.

2. System Architecture: PromptCraft Studio AI

The application is architected around a 3-column responsive workbench layout ensuring zero layout shift and sub-millisecond local state synchronization:

1. Template Navigator (Left Column)

Instant search filtering by keyword or tags, domain category switching (All, Coding, Compliance, Analysis, System), dynamic variable count badges, cloning, deletion, and pre-seeded enterprise templates.

2. Editor & Dynamic Variable Binding (Center)

Monospace prompt template textarea, system persona input, automatic regex extraction of {{placeholders}}, reactive input fields, and real-time interpolated prompt preview with 1-click clipboard copying.

3. AI Quality Scorecard (Right Column)

Heuristic static analyzer scoring Clarity (35%), Specificity (35%), and Guardrails (30%) on a 0–100 scale, assigning quality tiers (EXCELLENT, GOOD, MODERATE, POOR) with actionable optimization recommendations.

4. Model Playground & FinOps Telemetry (Right Column)

Simulates token streaming (45ms interval) with abort control across Gemini 3.8 Flash High, Claude 3.7 Sonnet, and GPT-4o. Displays latency, token throughput, and exact USD transaction cost down to 6 decimals.

5. Critical Post-AI Manual Refactorings (Code Review)

As documented in REFACTORING.md, human code review identified four critical areas where raw AI output required significant manual correction and re-architecture:

Refactoring 1: Streaming Timer Memory Leak & Template Switch Race Condition

The Flaw: The AI initiated setInterval for token simulation without storing the timer handle in a useRef and without clearing it upon template switching or unmount. Switching templates mid-stream produced concurrent runaway intervals that corrupted output telemetry.
The Fix: Introduced streamTimerRef, coupled with a cleanup effect in useEffect([template?.id]) and an abort button that resets the generator state cleanly.

Refactoring 2: Regex Deduplication & Safe Placeholder Interpolation

The Flaw: The AI's initial regex returned duplicate entries when a placeholder (e.g., {{input_data}}) was referenced multiple times, causing duplicate input fields. Furthermore, unfilled variables were replaced with blank strings, destroying prompt context.
The Fix: Added Set deduplication to extractVariables and updated interpolatePrompt to preserve original placeholders until values are provided.

Refactoring 3: Schema Property Desynchronization (systemRole vs systemPersona)

The Flaw: Pre-seeded templates declared systemRole, while App.jsx and test assertions looked for systemPersona, causing blank inputs upon initial load and failing unit tests.
The Fix: Standardized on systemRole across all modules and implemented defensive fallback resolution: template.systemRole || template.systemPersona || ''.

Refactoring 4: Test Environment Decoupling (Pure ESM vs Bundler Pipeline)

The Flaw: AI suggested running tests importing raw JSX files directly in Node.js ESM mode, throwing ERR_UNKNOWN_FILE_EXTENSION.
The Fix: Decoupled logic tests into pure JavaScript executed natively by Node.js, while delegating JSX bundling verification to Vite's production build.
